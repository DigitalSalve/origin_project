# Scope of Work

**Purpose:** Output folder for the [Scope of Work SOP](../../06-operations/processes/SCOPE_OF_WORK_SOP.md). The SOW is the culmination of planning—it synthesizes expected project requirements (from canon, architecture, behavior, integrations, feature requests, examination reports, intended user flows, implementation verification) into a single document that defines scope, deliverables, and work items, and ties execution to the Documentation Process and feature-request discipline.

**Authority:** The living Scope of Work document is `SCOPE_OF_WORK.md` in this folder. Optional dated snapshots (e.g. at phase gates or releases) use `YYYY-MM-DD_SCOPE_OF_WORK_SNAPSHOT.md`.

**When to add or update:** When you need a formal SOW for a phase, release, or body of work. Follow the [Scope of Work SOP](../../06-operations/processes/SCOPE_OF_WORK_SOP.md) to create or update `SCOPE_OF_WORK.md` and to define work items and execution.

**Project-agnostic:** The SOP and SOW structure are project-agnostic; each project fills the SOW with its own requirements, deliverables, and work items.
